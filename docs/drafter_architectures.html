Hidden-State Speculative Drafters — Architecture Comparison

Four ways to draft K future tokens from a frozen transformer's hidden states. The frozen backbone runs once on the prompt and exposes context hidden states; a small trainable drafter proposes K tokens; the backbone then verifies them. The differentiator is how each draft position gets its information — context only, causal token feedback, or iterative joint refinement.

Frozen backbone Context hidden / KV Trainable drafter block Predicted hidden Token-embedding feedback Draft token out

① Old flow matcher (chunked / hidden-KV, stage 1–4)

All K hiddens predicted in parallel from context only, by integrating a flow velocity field (1–2 Euler steps from a delta init). Bidirectional self-attention, but no token feedback.
acc@4 ≈ 0.45 (ceiling)live ≈ 0.96×. Capacity/data could not break it.

② EAGLE-style (causal token feedback)

One shared drafter block, applied autoregressively. Each step consumes the previous predicted hidden and the embedding of the token it decoded, then predicts the next hidden. Strictly causal — K sequential passes.
acc@4 0.52–0.80 · live 1.02× (first >1×)

③ V3 flow matcher (token-conditioned bidirectional refiner)

Flow-matching velocity field over the whole K-block, refined for N iterative steps. Each step re-decodes the block, embeds the tokens, and re-conditions the next velocity prediction — and all K positions self-attend (bidirectional), so any position can be revised.
accept > old flow (every domain)but < EAGLE · slower

④ DFlash-style (block diffusion in token-embedding space)

Diffuse over masked token embeddings (absorbing-state), not raw hiddens. Conditioned on multiple target layers (concat + project) and the target's KV directly. Big blocks (16) + tree verification.
production: real speedups (vLLM/SGLang) — the SOTA of this family

Key takeaways from our experiments: token feedback is the lever (EAGLE broke the ceiling and crossed 1× live; flow iteration without feedback was inert in a controlled 2×2 ablation). V3 added feedback to a bidirectional iterative flow and beat the old flow matcher on acceptance, but did not beat causal EAGLE and was slower. DFlash suggests the unexplored levers for the flow/diffusion family: diffuse in token-embedding space with absorbing masks (not raw hidden space), condition on multiple target layers, and use large blocks + tree verification. Note: live speedup on this backbone is additionally capped by the hybrid linear-attention verify+commit double-forward, independent of the drafter.
